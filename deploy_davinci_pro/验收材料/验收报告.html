3. 硬件平台确认

达芬奇Pro 的核心板可换（35T / 100T / 200T）。实际型号不能靠猜， 本次通过 JTAG 直接读取器件属性确定：

DEVICE: xc7a200t_0  PART=xc7a200t  IDCODE=00010011011000110110000010010011

IDCODE 0x13636093 对应 XC7A200T，与卖家文档常写的 XC7A100T 不同。 据此有两个关键结论：

  • 正确器件字符串是 xc7a200tfbg484-2。200T 没有 fgg484 封装 （FGG 为无铅焊球、FBG 为有铅焊球，二者焊盘尺寸相同但并非每个器件都提供两种）， 误用会直接报 [Common 17-162] Invalid option value。
  • 正因为 FGG/FBG 焊盘兼容，底板引脚号在 100T 与 200T 核心板之间通用， 引脚约束无需重写。

6. 关键问题与修复

发现并修复一个会导致上板功能永久失效的缺陷（原工程遗留）。
该缺陷在仿真中完全不显现，只有到手写板级测试台并核查综合日志后才暴露。

6.1 现象

原 board_top.v 将期望判决 ROM 声明为 1 位宽存储器：

reg       exp_rom [0:7];        // 原写法 —— 1 bit 宽
reg [7:0] exp_rom [0:7];        // 修复后

Vivado 综合器对该写法只给一条 warning，然后整条初始化被静默丢弃：

INFO:    [Synth 8-3876] $readmem data file 'feat_all.mem' is read successfully
WARNING: [Synth 8-2898] ignoring malformed $readmem task: invalid memory name   ← exp_dec.mem 被丢弃

6.2 后果推演

位流中 exp_rom 全部为 0，而期望值为 1,1,1,1,0,0,0,0。 因此前 4 例（判决应为 1）全部比对失败、后 4 例（判决应为 0）侥幸通过， pass_count 恒为 4，LED3（8/8 指示灯）永远不会点亮。

6.3 为什么长期未被发现

RTL 仿真器可以正常处理 1 位宽存储器，因此工程自带的仿真一直 8/8 全过。 这暴露了一个容易误判的认知：「仿真通过」不等于 ROM 内容真的进入了位流。 原工程说明也注明未在真实板卡上验证过，缺陷因此一直潜伏。

6.4 修复与验证

判据（综合日志）修复前修复后
Synth 8-3876 成功读取条数67
Synth 8-2898 非法存储器条数10

修复后 7 个 ROM 全部正确预置（含关键的 exp_dec.mem），板级仿真与核心仿真 仍全部通过，说明修复未引入回归。

可复用的排查准则：综合日志中每一个 $readmemh 都必须有一条对应的 8-3876 read successfully；出现任何 8-2898 ignoring malformed 都是 真实缺陷而非无害警告。

6.5 部署过程中排除的另一个环境故障

实现阶段曾出现无报错挂起：日志停在综合结束之后再无输出，进程存活但 CPU 时间 几乎不增长，中间文件时间戳冻结。定位为系统盘剩余空间不足（约 4 GB）导致 Vivado 临时 目录写满。将 TEMP/TMP 重定向至大容量分区后流程恢复正常 （构建 44 分钟挂起 → 重定向后正常完成）。

附注：该重定向仅适用于构建阶段；下载与回读阶段须使用默认临时目录， 否则硬件服务器连接失败（Labtools 27-3733）。此差异已固化进一键脚本。
