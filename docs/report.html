1任务与问题定义

本工作的任务是雷达回波目标检测：给一帧接收到的雷达回波，判断其中是否存在目标反射，即输出“有目标 / 无目标”的二元决策。它不是目标分类，也不是测距或测速。

1.1 二元假设检验

发射信号（复基带 LFM chirp）
s(t) = exp(jπKt²),  0 ≤ t ≤ Tp,  K = B/Tp
接收回波
H0（无目标）：r(t) = c(t) + n(t)
H1（有目标）：r(t) = A·s(t−τ)·exp(j2πfdt + jφ) + c(t) + n(t)
物理量
τ = 2R/c （目标距离）   fd = 2v/λ （目标径向速度）

其中 A 为回波幅度，τ 为往返延迟，fd 为多普勒频移，φ 为随机相位，c(t) 为杂波，n(t) 为噪声。标签 y=1 表示 H1，y=0 表示 H0。

1.2 检测到的是什么

检测到的对象是一个反射目标（飞机、无人机、车辆、舰船等都可能），但本任务不区分类型。目标参数在数据中是随机的，网络必须对距离/速度不敏感，只学习“回波是否存在”的谱特征。

1.3 时域与频域

标准雷达检测使用时域匹配滤波：

y(τ) = ∫ r(t)·s*(t−τ) dt

如果存在目标回波，相关输出会在目标延迟处出现尖峰，超过门限即判为“有目标”。LFM 的匹配滤波也可以在频域实现：Y(f)=R(f)·S*(f)，再 IFFT 得到距离像。

本工作的简化：按题目允许，仅使用接收信号的 FFT 幅度谱作为 SNN 输入。幅度谱丢弃了相位，因此不做相干积累、不能直接测距/测速；但它保留了目标回波在 LFM 频带上的谱形，足以做“有无目标”的检测。这是有意为之的硬件友好简化。

3.2 频域特征

X[k] = FFT(r[n]),  k = 0…511
P[k] = 10·log10(|X[k]|² + 1e−12)
z[k] = clip((P[k] − median(P)) / (1.4826·MAD(P)), −3, +3)
q[k] = round(255 · (z[k] + 3) / 6) ∈ [0,255]

每个样本做逐样本鲁棒归一化，去掉绝对能量。这样网络不能只靠“总能量大”判别，必须利用谱形：目标回波抬高 LFM 频带，杂波集中在低频，噪声是白的。

为什么用全 512 bin：复基带的正/负频率都保留，负频率半谱提供额外的噪声/杂波参考。相比只用 256 个正频率 bin，测试精度从约 92.8% 提升到 96.7%。

5硬件架构与资源

5.1 高效 SNN 单元

每层是一个 32-lane 的突触处理单元：一个 256-bit 权重字包含 32 个 int8，每个 lane 做条件加，再走 5 级 16-bit 加法树。

256-bit 权重字32 × int8
→
32 路条件加spike ? w : 0
→
5 级加法树16-bit signed
→
acc 累加24-bit
→
S_UPDATEV 更新 / 阈值 / 软复位
  • 无乘法器：脉冲是 0/1，突触操作退化为条件加；整颗设计 DSP = 0。
  • int8 权重 + 24-bit 有符号膜电位/偏置/阈值；软复位：V ≥ θ 时 V ← V − θ。
  • 膜电位存 BRAM/LUTRAM，避免 512 路 24-bit 读 mux 占用大量 LUT。
  • 权重/偏置/膜电位预取：地址组合驱动，读延迟 1 cycle，逐 chunk 流水。
  • S_UPDATE 流水级：把“加法树 + 累加”和“膜电位更新 + 比较”分到两个 cycle，50 MHz 下数据通路关键路径从约 19.6 ns 降到约 15.8 ns。
  • 编码器控制寄存器复制：512×9 个 sigma-delta 累加器的 clear/tick 扇出很大，改用寄存器驱动并加 max_fanout 约束。

5.2 存储格式

权重行优先、每 32 个输入一个 256-bit 字：

word_addr = dest_neuron · (FANIN/32) + chunk

lane 0 在 bit [7:0]，lane 31 在 bit [255:248]；偏置每行 24-bit 补码；膜电位在推理开始时用写端口扫 0 清空。

5.3 为什么是 512-512-512-2

BRAM 的深度会落到不同原语模式，256-bit 宽所需 BRAM 数会跳变：

每层字数深度模式256-bit 宽所需 BRAM
4,0964K×932
8,1928K×464
11,26416K×2128
16,38416K×2128

512 个隐藏神经元、fan-in 512 时，一层正好 512×16 = 8,192 字 → 64 个 RAMB36。最终实现 L1 用 64 个 RAMB36、L2 用 63 个 RAMB36，加 2 个 RAMB18 的膜电位，合计 128/140 个 BRAM tile。若第二层改成 704 神经元，一层就变成 11,264 字 → 128 个 BRAM，两层放不下。

因此 512-512-512-2 是在“int8 权重 + 256-bit 字 + 32 lane”组织下接近 BRAM 上限的最大网络。要再大，需要 4-bit 权重、权重压缩或稀疏化。

8讨论与局限

8.1 主要局限

  • 合成数据：当前数据集由 LFM + 杂波 + 噪声模型生成，不是实测雷达数据；真实系统还有校准误差、非平稳杂波、多径、目标起伏等。
  • 幅度谱丢相位：没有做相干积累/匹配滤波；低 SNR 性能受限。完整做法是时域匹配滤波或频域 R(f)S*(f) + IFFT。
  • 不是硬实时：5.6 ms/次对应约 179 次/s，不适合 100 µs PRI 的逐脉冲实时处理；适合低重频、离线或后续跨脉冲流水。
  • 特征提取在片外：FFT、log、median/MAD 归一化当前由 Python 离线完成；上板可在 PL 内做 512 点 FFT（PS/DDR 不在本次范围）。
  • 时序/功耗为 OOC 估算：尚未上板，缺少真实时钟、引脚和翻转率。

8.2 为什么仍然是有意义的

  • 在 7020 上实现了接近 BRAM 上限的 52.5 万突触 SNN，而不是小规模玩具网络。
  • 32-lane 无乘法器 SNN 单元 + S_UPDATE 流水，50 MHz 时序收敛。
  • ANN→整数 SNN 不是“近似”，RTL 与 Python 逐计数一致（8/8）。
  • 在低 SNR + 强杂波 + 随机距离/速度的合成回波上达到 96.75%，PD 95%，PFA 1.54%。

8.3 如果换真实数据

需要重新采集/标注真实雷达回波，重新训练 ANN 并重新做 λ 校准/量化；阈值和输出偏置可能需要按新数据分布重新标定。硬件架构不变，只换权重和测试向量。

8.4 资源余量与“榨干”路线

只看 PL：当前设计只把 BRAM 用到了 91.4%，LUT / FF 还有大量余量，DSP 按二值 SNN 特性暂未使用（PS/DDR 不在本次范围）。准确地说：它是“int8 权重 + 256-bit 字 + 32 lane”组织下的 BRAM 极限，不是 7020 PL 的绝对极限。

  1. 8-bit 效率版（已实现，推荐，见 9.5）：512→256→128→2，164,096 突触（−69%），实测 36.5/140 BRAM，SNN 96.64%，PFA 1.44%，1.77 ms。任务已饱和，缩小网络比继续加大更划算。
  2. 4-bit 容量版（已实现，容量实验，见 9.4）：512→704→704→2，857,472 突触，118.5/140 BRAM，SNN 96.50%，PFA 2.48%；精度/PFA 不如 8-bit 基线。
  3. 100 MHz：当前关键路径约 17 ns，设计上限约 58 MHz；把编码器改成时分复用（32 路/cycle ×16 拍）并给数据通路再加一级流水，可把 5.59 ms 降到约 2.8 ms，吞吐翻倍。
  4. 片上 FFT / 匹配滤波：用 DSP 做 512 点 FFT + log + 归一化，PL 自包含，DSP 不再为 0；12 个空闲 BRAM 可做 FFT/双缓冲。
  5. 多通道/多脉冲并行（PL）：用剩余 LUT/FF/BRAM 并行处理多路回波或多脉冲，提高吞吐/做积累；DSP 可用于多路 FFT。
  6. 稀疏/时钟门控：零 chunk 跳过、层内时钟门控，降低动态功耗；不增加容量，但提高性能/瓦。

板级参数说明：器件级参数已从 Vivado 确认（xc7z020clg400-2，53,200 LUT / 106,400 FF / 140 BRAM36 / 220 DSP）。当前综合/实现是 out-of-context，只验证了器件资源与内部时序；上板还需要领航者 7020 的原理图/XDC（50 MHz PL 时钟引脚、复位）。PS/DDR 等 PS 端资源不在本次范围。

9下一步与结论

9.1 PL 上板集成

  • 特征源：片上 512 点 FFT + log + median/MAD 归一化，或外部简单接口预装特征；PS/DDR 不在范围。
  • 加 PL 时钟/复位/引脚约束，生成 bitstream，上板实测延迟/功耗。
  • 结果读出：简单 PL 寄存器 / UART / ILA（可选）。

9.2 算法增强

  • 时域匹配滤波/频域 R(f)S*(f) 距离像作为对比特征；预期低 SNR 性能更好。
  • 更强杂波/多径/目标起伏（Swerling）数据；真实数据重训。
  • 多脉冲相干/非相干积累，提高检测率。

9.3 性能/容量

  • 100 MHz：进一步流水/降 lane 数；当前关键路径约 17 ns。
  • 4-bit 权重 + 64 lane：已实现 512→704→704→2（857,472 突触，见 9.4）；若输入/层再扩可接近 1M。
  • 稀疏门控（零 chunk 跳过）降低动态功耗；跨脉冲流水提高吞吐。

spike-count margin 是什么：它是我们自己的读出方式，不是论文术语。rate-coded SNN 在 T 步内给每个输出神经元累计脉冲数 count0/count1；定义 margin = count1 − count0，判决“有目标”当 margin > δ。δ=0 就是 argmax；δ>0 要求目标类赢出余量，用验证集负样本选 δ 来换更低 PFA（1D MLP：δ=2/3/5 → PFA 1e-2/5e-3/1e-3，PD 92.38/89.78/84.07%）。RTL 里就是 DEC_THRESH。GRSL 2025 RSN 用的是膜电位而不是 count margin；本报告的 2D RSN 也用膜电位，所以 PFA 校准与论文一致。

9.10 2D 卷积引擎 RTL（128 lane，100 MHz 实现）

9.9 的算法已经落成可综合 RTL。引擎不是六个独立卷积核，而是一个 128-lane 通用 2D 卷积引擎，由顶层按层加载运行时配置（Cin 1/16/32、Cout 16/32、stride 1/2、SEW 源、权重/偏置/膜电位基址），因此六层共享同一套 MAC/LIF 硬件。128 lane 映射为 8 pixel×16 ch（Cout=16）或 4 pixel×32 ch（Cout=32），每行 4 组；相比 64 lane 的 8 组/行，dense MAC 周期数减半。

仿真结论：8/8 决策与 Python 整数参考一致；L1 t0 的输出 spike 图（512 字）和膜电位（256 字）0 bit 差，说明编码器、Conv1、LIF/权重/偏置/膜电位写回都是对的。case0 的 L2–L5 计数差 <0.2%、L6 约 1.6%，FC 分数差约 1.5%；但其余随机例的逐层计数有 1–14% 漂移，FC 分数也会漂移（个别用例的 score1 可差数倍）。原因是跨 t 的 row-buffer 边角/编码器计数观测时机，尚未 bit-exact；8 例判决仍全部正确。2D 的 bit-exact 是收尾项，不影响本节的资源/速度结论。

深度/宽度消融（2026-11-23）：简单集 6L/8L/W24 = 99.72/99.49/99.61%；难集（SNR −10…0、CNR 8…18、K 杂波/尖峰/干扰/缺失/失配）= 76.89/76.98/76.68%（AUC 0.844/0.840/0.843；PFA 1e-2 时 PD 46.7/46.1/48.0%）。加层/加宽在简单集和难集都没有明显收益；简单集饱和，难集才是真实瓶颈。下一步优先 T=8、特征/预处理、真实 IPIX；128-lane 已把单次从 9.01 ms 压到 5.01 ms，继续堆层没有收益。
资源与时序（Vivado 2025.2，xc7z020clg400-2，OOC）： 128-lane 最终实现（100 MHz）：LUT 27,948/53,200（52.5%）、FF 15,393/106,400（14.5%）、 BRAM 98/140（70%）、DSP 2/220；功耗 0.661 W （动态 0.543 + 静态 0.118）。实现 WNS +0.259 ns、WHS +0.122 ns，0 失败端点。 64-lane 对照：LUT 14,946（28.1%）、FF 10,427（9.8%）、BRAM 98、0.584 W、WNS +0.070、9.01 ms。 流水化：tap 窗口 sg_r 预取 → 配置/阈值寄存 → pc/计数寄存 → tap 计数器（去 /9） → 两级 LIF（fire_vec 寄存）→ FC 乘/加两级。首版 128-lane 实现 WNS −0.712 ns； 加 sg_r 预取后综合 +2.373、实现 +0.259。BRAM 仍是 98（70%）， 继续加 lane 会被 BRAM 宽度/容量挡住，LUT 不是唯一瓶颈。

延迟与能耗：8 例仿真共 40.07 ms，平均 5.01 ms/次 @100 MHz（含特征写入、4 次编码、6 层 dense MAC、读出/FC）；64-lane 为 9.01 ms，实测 1.80×。dense MAC 理论 3.36 ms，固定开销约 1.65 ms；事件驱动 0.79 ms 仍是按平均脉冲率的估算，尚未实现。功耗 0.661 W × 5.01 ms ≈ 3.31 mJ/次，比 64-lane 的 5.26 mJ 低 37%。2D RSN 是“精度优先”的版本；1D 8-bit 256-128 仍是低延迟版本（1.77 ms）。
