## 2. 任务内容

原始工程 `snn-radar-detector-main` 提供了一套时频二维脉冲神经网络加速器的 RTL 与定点权重，
但其 `deploy/` 部署包目标平台是**领航者 ZYNQ-7020**（`xc7z020clg400-2`），引脚约束为未填写的

本次工作的目标是把该设计**完整移植到达芬奇Pro 并实际上板跑通**。

## 3. 硬件平台确认

达芬奇Pro 核心板可换（35T / 100T / 200T），**实际型号不能靠猜**。本次通过 JTAG 直接读取：

```
DEVICE: xc7a200t_0  PART=xc7a200t  IDCODE=00010011011000110110000010010011
```

IDCODE `0x13636093` 对应 **XC7A200T**，与卖家文档常写的 XC7A100T 不同。由此得出：

- 正确器件字符串为 `xc7a200tfbg484-2`。**200T 没有 `fgg484` 封装**（FGG 无铅 / FBG 有铅焊球，
  焊盘尺寸相同但并非每个器件都提供两种），误用会报 `[Common 17-162] Invalid option value`。
- 因 FGG/FBG 焊盘兼容，底板引脚号在 100T 与 200T 间通用，引脚约束无需重写。

### 3.1 板级引脚约束

| 信号 | 引脚 | 电平 | 说明 |
|---|---|---|---|
| `clk50` | R4 | LVCMOS33 | 板载 50 MHz 有源晶振 |
| `rst_n` | U7 | LVCMOS33 | RESET 按键，低有效 |
| `led[0]` | W7 | LVCMOS33 | 核忙标志 |
| `led[1]` | Y7 | LVCMOS33 | 8 例全部跑完 |
| `led[2]` | Y8 | LVCMOS33 | 末例判决 |
| `led[3]` | V9 | LVCMOS33 | 8/8 全对标志 |

引脚来源：两处相互独立的公开工程约束交叉比对一致，并经综合实现验证——
6 个 IOB 全部绑定成功（`Bonded IOB = 6/285`），布局布线通过。

## 4. 设计架构

```
50 MHz 板载时钟 (R4)
      │
      ▼
  MMCME2_BASE ──► 100 MHz 核心时钟
      │
      ▼
board_top（本次补齐的板级外壳）
  ├─ feat_all.mem (8 KB ROM)  ──► 自检 FSM
  ├─ exp_dec.mem （期望判决） ──► 比对 pass_count

       σ-Δ 编码器 1024 通道
        → 6 层 2D Conv / LIF / SEW（128 lane 共享引擎）
        → 全局 max 池化 → int8 全连接 32→2
                              │
                              ▼
                         LED[3:0] 状态指示
```

纯 PL 自检型：上电后自动取入 8 组 1024 字节测试特征，逐例推理并比对期望判决。
单例约 5.82 ms，8 例合计约 46 ms（仿真实测 `done_all asserted after 46 ms`）。

## 6. 关键问题与修复

> **发现并修复一个会导致上板功能永久失效的缺陷（原工程遗留）。**
> 该缺陷在仿真中完全不显现，只有到手写板级测试台并核查综合日志后才暴露。

### 6.1 现象

原 `board_top.v` 将期望判决 ROM 声明为 **1 位宽存储器**：

```verilog
reg       exp_rom [0:7];        // 原写法 —— 1 bit 宽
reg [7:0] exp_rom [0:7];        // 修复后
```

Vivado 对该写法**只给一条 warning，然后整条初始化被静默丢弃**：

```
INFO:    [Synth 8-3876] $readmem data file 'feat_all.mem' is read successfully
WARNING: [Synth 8-2898] ignoring malformed $readmem task: invalid memory name   ← exp_dec.mem 被丢弃
```

### 6.2 后果推演

位流中 `exp_rom` 全为 0，而期望值为 `1,1,1,1,0,0,0,0`。因此前 4 例（判决应为 1）全部比对失败、
后 4 例（判决应为 0）侥幸通过，`pass_count` 恒为 **4**，LED3（8/8 指示灯）**永远不会点亮**。

### 6.3 为什么长期未被发现

**RTL 仿真器可以正常处理 1 位宽存储器**，因此工程自带仿真一直 8/8 全过。
这暴露了一个容易误判的认知：「仿真通过」**不等于** ROM 内容真的进入了位流。
原工程说明亦注明未在真实板卡验证，缺陷因此一直潜伏。

### 6.4 修复与验证

| 判据（综合日志） | 修复前 | 修复后 |
|---|---:|---:|
| `Synth 8-3876` 成功读取条数 | 6 | **7** |
| `Synth 8-2898` 非法存储器条数 | 1 | **0** |

修复后 7 个 ROM 全部正确预置（含关键 `exp_dec.mem`），两层仿真仍全部通过，无回归。

> **可复用排查准则**：综合日志中每个 `$readmemh` 都必须有对应的 `8-3876 read successfully`；
> 出现任何 `8-2898 ignoring malformed` 都是真实缺陷而非无害警告。

### 6.5 排除的另一个环境故障

实现阶段曾出现**无报错挂起**：日志停在综合结束后再无输出，进程存活但 CPU 时间几乎不增长，
中间文件时间戳冻结。定位为**系统盘剩余空间不足（约 4 GB）导致 Vivado 临时目录写满**。
将 `TEMP`/`TMP` 重定向至大容量分区后恢复正常（44 分钟挂起 → 重定向后正常完成）。

> 附注：该重定向仅适用于构建阶段；下载与回读须用默认临时目录，否则硬件服务器连接失败
> （`Labtools 27-3733`）。此差异已固化进一键脚本。

### 建议补充的现场证据

1. **LED 实拍照片**（首选）：按 RESET 后拍摄板上 4 个 LED，LED1 与 LED3 同时点亮即为 8/8 全对。
   这是最直观、最低成本的现场凭据。
2. **VIO 机器读数**（可选）：在 `board_top` 中例化 VIO 核，暴露 `pass_count` 与 8 位判决串，
   即可通过 JTAG 直接读出硬件实测结果，无需目视判读。代价是需重新实现（约 60 分钟）。

### 关于结论边界的说明

本报告可以确证的是——位流针对正确器件构建、时序收敛、ROM 内容确实进入位流、
位流已正确载入 FPGA。至于「8 个测试用例在硬件上的判决结果为 8/8」，已有仿真层面的完整证据链
（同一套 RTL、同一份 `.mem` 数据，已逐字节核对一致），但硬件现场的最终确认仍需
**LED 目视或 VIO 读数**二者之一。

建议如实说明这一边界，而不把仿真结论表述为硬件实测结论。
